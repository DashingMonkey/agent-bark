## 配置文件

位于平台配置目录，一般通过 GUI 修改，也可手工编辑：

| 平台 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\agent-bark\config.json` |
| macOS | `~/Library/Application Support/agent-bark/config.json` |
| Linux | `~/.config/agent-bark/config.json` |

```jsonc
{
  "server": { "port": 36573, "token": "首次启动自动生成" },
  // 状态音效：每个状态可选一个内置音效，effect 为空 = 不响（默认）。
  // 可选：chime 风铃 / confirm 确认 / success 成功 / drop 水滴 /
  //       pluck 弹拨 / glass 玻璃 / error 错误 / deep 低叮
  "notify": {
    "thinking":   { "effect": "", "plays": 1 },   // 思考（新回合开始）
    "waiting":    { "effect": "", "plays": 1 },   // 等待（等待确认 / 等待输入）
    "completed":  { "effect": "", "plays": 1 },   // 完成
    "failed":     { "effect": "", "plays": 1 }    // 失败（明确的任务失败信号）
  },
  "rules": {
    "aggregate_window_ms": 1500,       // 聚合窗口：同 agent 同类事件在窗口内合并为一条
    "quiet_hours": [],                 // 免打扰时段，如 ["23:00-08:00"]（可跨零点）
  },
  "channels": {
    "bark":    { "enabled": false, "url": "https://api.day.app/YourKey" },
    "webhook": {
      "enabled": false,
      "url": "https://open.feishu.cn/...",
      "method": "POST",
      "template": "{\"title\": \"{title}\", \"body\": \"{body}\", \"agent\": \"{agent}\"}"
    }
  },
  "agents": [{ "kind": "claude-code", "enabled": true }],
  "glow": {
    "enabled": true,              // 屏幕光效总开关（启动 / 停止）
    "edge": true,                 // 边缘光效总开关：关掉后只收边缘灯带，全屏特效照常
    "fullscreen": true,           // 全屏特效总开关：每次颜色亮起时整屏补一次特效
    "monitors": "all",            // all=全部显示器 / 数字=第 N 块屏（UI 的「1.显示器1(1920*1080)」）
    // 边缘 / 全屏的类型按状态各选各的（GUI「屏幕光效」两列四行，与「声音」区同款）：
    //   edge_effects  ：none=不亮 / breathing=呼吸 / comet=流光
    //   burst_effects ：none=不放 / fog=雾散 / scan=扫描 / rain=矩阵雨
    "edge_effects":  { "thinking": "comet",     "waiting": "comet",     "completed": "comet",     "failed": "comet" },
    "burst_effects": { "thinking": "scan",      "waiting": "scan",      "completed": "scan",      "failed": "scan" }
  },
  "widget": {
    "enabled": true,              // 悬浮窗总开关（关闭后不创建窗口；GUI「悬浮窗」页 / 右键菜单改）
    "x": -1,                      // 卡片左上角（逻辑像素）；-1 = 未放置过，按主屏右上角打开
    "y": -1,
    "pinned": false,              // 固定位置：true 时不响应拖动（悬浮窗右键菜单里切换）
    "dock_side": null,            // 靠边隐藏方向：null / "top" / "left" / "right"；x/y 记住展开位置
    "dock_monitor": null          // 停靠显示器名称，自动记忆，用于混合缩放多屏恢复
  }
}
```

**约定与注意事项**：

- `agents` 段存的是**字符串 id**（不是枚举），所以老配置里残留已下线 agent 的 id 不会导致解析失败；
- 手改配置漏键不会解析失败，按默认值补齐；文件不是合法 JSON 时**拒绝写入**（避免覆盖你的配置），UI 会提示「配置读取失败」；
- 端口 / 鉴权 token 改过之后，运行中的事件服务器仍用启动时的值——UI 会提示「需重启生效」；
- 配置采用原子写入（临时文件 + fsync + rename）；
- `widget.{x,y,pinned,dock_side,dock_monitor}` 由悬浮窗自己的拖动 / 右键菜单写入，主窗口保存配置时会保留这些字段（不会被旧值覆盖）；
- 旧版的 `glow.effect` / `glow.fullscreen_effect`（全局类型）只作**迁移源**：升级后四态各按它补齐一次，之后再改它们不再生效（运行时只读 `edge_effects` / `burst_effects`）。

### 悬浮窗显示与靠边收起

悬浮窗启用后自由悬浮时始终可见；拖到屏幕外缘后才会贴边收起。原来的自动隐藏开关已移除，旧配置中的 `auto_hide` 会被忽略。

- **托盘单击找回**：左键单击托盘图标，已启用且停靠的悬浮窗展开 2 秒；重复单击重新计时。关闭悬浮窗时单击不会启用它。双击托盘仍打开主面板，右键仍打开菜单。
- **状态变化展开**：停靠时，会话新增、移除、显示状态类别变化，以及完成 / 失败 / 手动中止事件会自动展开 5 秒；主会话与子代理均适用。类别与行的显示颜色一致：思考 / 执行工具属于同一工作状态，等待输入 / 等待权限属于同一等待状态，等待子代理 / 收尾属于同一暂停状态；同类切换不展开、不续时。后续类别变化重新计时，重复快照、心跳时间与工具计数更新也不续时。启动初始快照只恢复显示，不算新的变化。
- **悬停保持**：鼠标移上去后持续展开；离开时若展开时间未到（托盘单击 2 秒、状态变化 5 秒），保留剩余时间，否则约 350ms 后收回。拖动、菜单与详情展开期间也不会收缩。等待确认状态本身不会无限保持展开。
- 完成 / 失败行约 6 秒后从列表中过期；过期只更新内容，不触发展开。手动中止行保持中性色。
- **子代理行也在卡片里**：细连接线与缩进、稳定标签 `子代理 01 / 02 / …`、较小字号；临时展开只影响悬浮窗，不改变通知、音效和全屏特效对子代理的过滤。
- **固定宽度 280px，不提供宽度切换**。主会话行高 32px、子代理行高 29px；列表通常最多显示 192px，超出后内部滚动，底部显示会话数与待处理数。所有会话均保留，屏幕可用高度不足时进一步缩短列表。
- **父行被手动终止时**，只要它还有子代理在跑，父行就**常驻**标着 `手动终止`（仅在状态变化时临时展开，不会持续撑开窗口），子代理改标 `等待子代理`；子代理全清后整棵子树一起收掉。见下节「手动终止（`run_aborted`）怎么显示」。
- **单工作区显示 Agent 名，多工作区优先显示项目名**：Agent 身份由品牌图标及悬停详情补充；没有项目名时回退为 Agent 名。长名称保留有区分度的末尾。
- **等待与失败使用底色和 1px 内描边**：等待确认 / 等待输入为橙色，失败为红色，深浅主题分别配色；深色失败行增加亮红文字与左侧标记。手动终止使用中性色。
- **悬停详情优先在右侧**：鼠标停留约 220ms 后显示 Agent 身份及完整工作区名（可换行）。右侧不足 180px 时放在卡片下方，与卡片同宽、左右对齐，间隔 8px。提示和菜单出现时按需扩大原生窗口，收起后还原；靠近屏幕底边时临时上移，保证详情可见，不把临时位置写入配置。
- **子代理有稳定编号和层级连接线**：编号不会因相邻会话结束而重新排序；字号 11px（主行 12px），首级缩进 30px，后续每级增加 11px、最多两级。悬停可确认 Agent 和工作区。
- **靠边隐藏**：拖动时将卡片或鼠标靠近屏幕工作区顶部或左右边缘（6px 内），卡片对应边亮起提示，松手后滑动收起，只留 6px 窄边。移入缓动展开（260ms），移出约 350ms 后缓动收回（220ms），中途移入会从当前位置反向展开；系统启用减少动画时保留 160ms 的简短过渡。展开后仍是横向卡片。多屏之间的接缝不吸附；窄窗留在工作区内，不覆盖邻屏或任务栏。
- **停靠状态会记住**：重启恢复原边缘与展开位置；拖离边缘、右键「取消靠边隐藏」或启用「固定位置」可退出。拖出后需先离开边缘区域，才能重新吸附，避免刚拖出又吸回。
- **右键菜单**：打开主面板、固定位置、取消靠边隐藏（停靠时出现）、关闭悬浮窗。固定位置后显示标记，并退出停靠。

### 子代理怎么显示

子代理**看得见、但不打扰**——悬浮窗使用连接线与编号，事件流保留 `↳` 和子代理徽标：

| 位置 | 子代理的表现 |
| --- | --- |
| 悬浮窗 | 细连接线 + 缩进，标签为稳定的 **`子代理 01 / 02 / …`**，字号小一号；悬停详情显示 Agent 和完整工作区 |
| 事件流「运行中会话」 | `↳` + 缩进 + 灰色「子代理」徽标 + 血缘小字 `← …8ec9f`（父会话 id 尾 6 位，仅展示用）；父行缺席时上面有一行占位父行 |
| 事件历史 | 品牌色「子代理」徽标 + 名字与正文弱化 |

判据是后端下发的 `SessionStatus.parent`（**父会话 id 本体**）：**有这个字段就是子代理**——
它来自事件的 `parent_session_id` 血缘边，与 `is_subagent` 同一份来源。父子行由
`app/src/api.ts` 的 `sessionRows()` 排成「父行 + 它的子行紧跟其后」的树序（同级按开始时间倒序），
认亲用**完整 id 精确比对**（截成尾 6 位会在多会话并存时认错，见下）。

> **「是不是子代理」不要用 `depth === 0` 推断**：行的深度会被改（父行被摘掉后子树会顶格平铺），
> 悬浮窗为此带一个显式的 `Row.subagent` 标记，图标 / 连接线 / 弱化样式全看它——否则会出现
> 「子代理标签 + 根行图标」这种自相矛盾的一行（实测抓到过）。

> **血缘是回填出来的，不是一次写死**：`SessionStatus.parent` 在建档时写，但建档那条事件可能
> 拿不到血缘——DSH 插件的心跳在启动时读一次 `session.header.parentSession` 就缓存住，会话头
> 异步加载时会读到空，而 keepalive 心跳**不建档**（防幻影行），于是这条子代理会终生被当成
> 主会话、与真正的会话并排显示。（ZCode 的子代理血缘来自**日志看门狗的合成事件**——子代理
> 不触发 hook，`turn.started` / `tool.call.started` 行的 `context.parentSessionId` 由看门狗折成
> 带血缘的事件，走的是同一条建档/回填路径。）所以 daemon 在**任何带血缘的在位事件**上回填
> （`state.rs` 的 `backfill_lineage`：Activity、ToolFinished、授权请求 / 提问、工具失败），
> 回填算结构变化、快照立即推。只在「当前没有父」时写，不覆盖已有归属；自指血缘（父 = 自己）
> 在建档与回填两条路径上都被拒绝——否则前端只剩一条没有徽标、没有 prompt 的假行。

**父行不在本批快照里时（父回合已结束 / 已从本地显示移除）**：补一行**占位父行**（`会话 …8ec9f`，
状态「已结束」，弱化渲染），子代理照常缩进在它下面。

- 为什么不是「顶格平铺到末尾」：平铺会让子代理紧跟在**上一行的子树**后面，被读成「挂在了那个
  会话下面」——实测踩过：两个工作区各开一个 DSH 会话时，A 会话的子代理显示在 B 会话的子代理
  行下面，用户看到的就是「子代理跑到另一个会话下面了」。给个占位父行，血缘才不外溢。
- 占位行是**合成**的（`SessionRow.placeholder`，不在 `store.sessions` 里）：没有状态、没有
  prompt；占位行仅用于排版，不会单独触发展开计时。
- 合成条件必须是「这个 id **不在快照里**」，不能用 `visited` 反推：子代理的 `started_at` 更晚、
  倒序下常排在父行前面，用它判「父不在」会合成一行与真父行同键的假行，真父行随后被静默吃掉。

### 手动终止（`run_aborted`）怎么显示

**不合成新行，就把已经显示着的那一行就地改掉**——用户按的停止，反馈应该落在他正在看的那一行上：

- 那一行改标 `手动终止`（中性色短横线，与失败红色区分）；
- **只要有子代理还在跑，父行就常驻**（不摘），子代理照旧缩进挂在它下面，状态改写成
  `等待子代理`——它们各自的事件相位描述的是**父回合**，父都终止了还写「执行工具」会误导；
- **子代理全部结束**（这棵子树空了）→ 父行连同子树一起收掉，不留残影；
- 会话被**重新唤起**（daemon 重新建档、又有活动事件）→ 标记清除，行回到真实相位；
- **保留时长不是固定的 5 秒**：只要还有活着的子代理引用这个父会话，标记就一直留着（`ABORT_HOLD_MS`
  只是「没有子代理时」的兜底）。固定时长会在子代理还在跑的时候把标记丢掉，父行随即只剩一行合成
  占位行——实测：用户按停止 51 秒后截图，看到的就是 `会话 …f1f23b`（DSH 的 `turn/end` 带
  `reason.kind=aborted`，插件归一成 `run_aborted`，事件其实到得了前端，是前端自己扔早了）。
- 实现要点：daemon 收到终态就摘条目，它比快照推送快（两条独立通道），所以「手动终止」的标记
  **从事件侧建立**（`widget.ts` 的 `abortedRows` / `abortedMemo`），不能只在「这一行还在快照里」
  时记录——否则父行会先消失，只剩一行合成占位行 `会话 …尾号`（实测踩过，那正是用户报的「难看」）。
  常驻行就地**替换**占位行（位置不变），所以子树不用动、也不会跨到别的会话下面。
- **占位行的名字一律还原**：只要这一行还有子在跑，就不摆 id 尾号——名字取「上一帧见到的样子」
  （每一行渲染时都留一份 `lastSeenRow`），实在没见过就退化成 `agent 名 已结束`（那个 agent 名是
  确定的：合成占位行时用的就是子代理的 agent，而子代理与父会话必然同 agent）。这条与「手动终止」
  无关，父回合**正常结束**后子代理还在跑时同样生效（那时标签是 `已结束`）。

不打扰的口径：子代理的完成 / 失败**不弹悬浮窗、不响音效、不放全屏特效**、也不发通知——
一个任务拆出十几个子代理时，逐个收尾都会变成噪音。

## 流光状态怎么来的

流光是**双通道**的：边缘灯带按会话表聚合推导（与 GUI「运行中会话」同一份数据），
全屏特效则是独立的**事件通道**——两层互不覆盖。

**边缘（常驻）**多会话并存时以最需要你处理的为准：

| 优先级 | 条件 | 角色 |
| --- | --- | --- |
| 1 | 任一会话 `等待确认 / 等待输入` | 🟠 **等待色**（流光） |
| 2 | 任一会话 `思考中 / 执行工具` | 🔵 **思考色**（流光） |
| 3 | 无活跃会话，且最近事件为 `run_completed` | 🟢 **完成色**（停留后淡出） |
| 3 | 无活跃会话，且最近事件为 `run_failed` | 🔴 **失败色**（心跳双脉冲，停留后淡出） |
| 3 | 无活跃会话，且最近事件为 `run_aborted`（用户主动中止） | ⚫ 收起（不亮） |

**全屏（一次性）**按事件触发：多会话并行时，**任一会话**完成 / 失败（明确终态），
哪怕其余会话还在跑，也会立刻以事件角色（完成 / 失败）补放一次全屏特效（类型按该角色
那一行的 `burst_effects`）；边缘继续表达剩余
会话的聚合状态。「有一个完成了」是值得立刻知道的事件，「还有的在跑」是持续状态，两者不互斥。

> 配色（`#rrggbb`）与角色名的对应只写在 `app/src-tauri/src/glow.rs` 的
> `GlowState::color` 一处，并有配套的锁配色测试；改色不需要动本文档。
> 边缘的具体表现按**状态**各选各的（`glow.edge_effects`：「无」/「流光」/「呼吸」，默认流光），
> 全屏同理（`glow.burst_effects`：「无」/「扫描」/「雾散」/「矩阵雨」，默认扫描），选「无」时对应通道不亮；
> 打开 `glow.fullscreen` 且触发角色那行没选「无」时，每次颜色亮起（状态真的变化、
> 终态重发，或多会话并行时的完成 / 失败事件）会在整屏补放一次，渐显渐隐；
> 同一状态的重复心跳不会重放。
>
> 唯一不重放的例外是**窗口重建**：显示器数量变化（热插拔 / 改「生效显示器」）时覆盖窗会
> 全量重建，此时注入的初始态只是一份「现在长什么样」的快照——颜色照常显示（还在跑的
> 会话必须看得见），但不会借它白闪一次整屏（见 `glow.rs` 的 `create_all` / `replay_burst`）。
>
> 覆盖窗是**置顶 + 点击穿透**的，并且**把整块显示器盖住**（底边只向外多 1 物理像素，见
> `rect_of`）——系统会按「无边框全屏应用」对待它（判据是「窗口是否遮挡整个桌面」，与多出来的
> 那 1px 无关），任务栏自己就退到下面去了。但任务栏刷新自己（被点击、通知闪烁、托盘变化）时
> 会短暂升到最上层，而屏幕**底部**那条光带恰好整条落在它的条带里（边条 + 向内约 60px 辉光，
> Win11 任务栏约 48px），表现就是「只有下方没有光效」。因此灯常驻亮着时（思考 / 等待）每 5s
> 会把覆盖窗重新置顶兜底一次（`glow::raise` / `keep_topmost`）；空闲与终态不抢层级。底部那圈
> 辉光会叠在任务栏上——点击穿透，不影响任务栏操作。
>
> 「屏幕光效」页的预览是**临时接管**：真实事件、保存配置、托盘重置或点「熄灭」都会立刻
> 结束它，几秒后也会自动恢复；连点多次预览只认**第一次预览前**的状态——否则恢复时会把
> 上一次的预览态当成真实状态，灯就再也灭不掉。

> 只有所有会话都结束后，**边缘**才会转完成 / 失败色——A 完成了但 B 还在跑时，边缘报完成
> 是骗人；但全屏特效不等：A 完成的瞬间就会补放一次完成色扫描。每 5 分钟主动核验来源状态，
> 只有明确结束信号才收档；日志静默或数据库读取失败时保留最后已知状态。
>
> **用户主动中止是独立的第三类终态**（`run_aborted`）：不亮失败色（不是失败）也不亮完成色
> （没跑完），没有别的会话在跑时**直接收起光效**；同时**不通知**（自己按的停止，人就在
> 键盘前）。各 agent 的中止信号不一样，已统一到这一类：
> - Qoder / Qoder CN：`SessionEnd`（实测只发它、不发 `Stop`）；
> - DeepSeek Harness：`turn/end` 的 reason 为 `aborted` / `interrupted`；
> - ZCode：它中断时**一个 hook 都不发**，由 daemon 读它的本地日志推断（非官方机制，见 agent-integration.md §6）；
> - WorkBuddy（监控型）：运行中的会话被**归档**。
>
> 正常回合里 `Stop` 之后紧跟的那条中止信号会被状态机当**终态回声**抑制，不会重复处理、也不会把完成色压成失败色。

### 状态音效什么时候响

「通知」页「声音」里给四个状态配的音效，与流光同一套状态语义：

| 状态 | 触发 |
| --- | --- |
| 思考 | 新回合开始（不带工具名的心跳，即 `UserPromptSubmit`）；同回合的工具心跳不重复响 |
| 等待 | `permission_required` / `input_required`（等你确认 / 输入） |
| 完成 | `run_completed`（多会话并行时某一个会话完成也会响） |
| 失败 | `run_failed`（静默和读取失败不触发失败色） |

用户主动中止（`run_aborted`）不响（自己按的停止）；子代理事件不响；托盘「静音」与免打扰时段内不响。默认全部未选 = 完全静音；播放次数范围 1~10。

## 开发说明

- Rust workspace 共 6 个成员 crate，核心 crate 均带单元测试：`cargo test --workspace`
  - 本机离线构建：默认 `~/.cargo`（rsproxy sparse）+ `--offline` 即可；仓库里的 `.cargo-home` 是更早准备的本地 registry，**不全**（缺 `serde_yaml` 等），别拿它当 `CARGO_HOME`。
- 前端：**两条都要跑**——`pnpm --dir app typecheck`（`vue-tsc --noEmit`，类型检查）
  与 `pnpm --dir app build`（`vite build`，产出 index/glow/widget/menu 四个入口）。
  注意 `build` **不含**类型检查（`package.json` 里是两个独立脚本），只跑 build 会漏掉类型错误；
  `build.bat` 也把 `pnpm typecheck` 单列为一个步骤。

### ⚠️ 构建桌面应用必须走 Tauri CLI（踩过的坑）

```powershell
cd app
pnpm tauri build              # 出二进制 + NSIS 安装包
pnpm tauri build --no-bundle  # 只要可执行文件（跳过打包，快一些）
pnpm tauri dev                # 开发模式（需要 vite 起在 5173）
```

**不要用裸 `cargo build --release`**。`tauri.conf.json` 里同时配了 `devUrl`（`http://localhost:5173`）和 `frontendDist`（`../dist`），选哪个由 Tauri CLI 注入的环境决定：直接 `cargo build --release` 出来的二进制会去连 `devUrl`，启动后页面显示 **「localhost 拒绝连接」**（此时 vite 并没在跑）。前端资源必须由 CLI 构建才会内嵌。

**怎么判断手上的二进制是哪种**（注意：在 exe 里搜 `localhost:5173` 区分不出来——Tauri 会把整份配置内嵌进二进制，正常的生产构建里也有这个字符串）：

1. 启动后页面报「localhost 拒绝连接」→ dev 模式；
2. 看构建脚本输出：`target/release/build/agent-bark-app-*/output` 里出现 `cargo:rustc-cfg=dev` 就是 dev 模式；
3. 想确认「前端确实内嵌了」：在 exe 里搜 `dist/assets/` 下的资源名（如 `assets/main-BlPIIZQF.js`），搜得到即已内嵌；
4. 最彻底的一招：起一个假 dev server 占住 `127.0.0.1:5173`（只记日志），再启动 exe——如果它来请求这个端口，就说明是 dev 模式构建。

- Hook 侧调试：设 `BARK_DEBUG=1`，hook 会在 stderr 打印上报结果（含失败原因，不含 token 明文）。
- 「关于」页检查更新的联调：设 `BARK_UPDATE_REPO=owner/name` 可把两个平台的查询指到别的仓库（默认 `dashingmonkey/agent-bark`）——指到一个**已发过版本**的仓库就能验证「发现新版本 → 下载新版本」这条路径，不必等本仓库先发版。
- 运行状态核验：每 5 分钟触发一次；托盘「检测运行状态」可立即触发。各 Agent 的数据库/日志监控继续使用原有秒级周期。静默不再自动终止会话，`BARK_STALE_AFTER_MS` 已移除。来源不可用时保留最后已知状态。事件流中的「移除」只清除本地会话显示并重新对齐光效，不停止 Agent、不产生终态或通知；缓存心跳不会重新建档，新的真实活动可恢复显示。Kimi Work 与豆包工作降级分支在日志连续 5 分钟无增长后停止合成心跳，仍保留会话。显示上限为 64 条，满时保留已有会话并提示移除停滞条目。具体支持范围见 [agent-integration.md](agent-integration.md)。
- Hook 进程的三条硬约束（见 `crates/bark-cli/src/lib.rs` 模块注释）：永远退出码 0；读 stdin 必须带超时；只读配置、绝不写盘。
- 验证某个 agent 到底读哪份配置 / 哪些事件真的会触发：见 [agent-integration.md 的「探针验证法」](agent-integration.md#13-探针验证法文档与实测冲突时用)。
